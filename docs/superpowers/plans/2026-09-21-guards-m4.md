# LH-M4 Implementation Plan — Run Guards

**Status: pending**


> **For agentic workers:** Implement task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Prefer small commits only when the user asks.

**Goal:** Make long-run safety limits configurable under TOML `[guards]`, enforce them in the orchestrator, finish with `run.finished(reason=guard_*)` (not silent continue), restore `GuardsSnapshot` on resume, and cover each guard with tests.

**Architecture:** Add `GuardsConfig` on `AppConfig`. Pass it into `run_agent*` / `AppState` like `ContextConfig` / middlewares. Keep counters on existing `GuardsSnapshot` (`llm_rounds`, `follow_up_rounds`, `started_at`). Add lightweight noop tracking on `PersistSession` (consecutive noop streak + last assistant text / todos fingerprint). After each main LLM completion and before follow-up injection, evaluate guards; on trip → emit `run.finished` with the matching reason, finalize checkpoint as `Completed` (or keep `Failed` only for true errors—**decision: guards use Completed + reason**, consistent with cancel using finished). Replace hard-coded `MAX_FOLLOW_UP_ROUNDS` with config. **Load `guards` from checkpoint** on cold/hot continue (today `PersistSession::new` always `new_now()` — fix in M4).

**Tech Stack:** Existing crate only. No chrono crate required (keep unix-seconds strings already used by `GuardsSnapshot`).

**Spec:** [docs/superpowers/specs/2026-09-18-long-horizon-design.md](../specs/2026-09-18-long-horizon-design.md) — §5 (LH-P1b), §13 decision #3 (noop → direct finish), §12 LH-M4.

## Global constraints

- Guard trips emit **`run.finished`** with `reason` in `{guard_llm_rounds, guard_timeout, guard_noop, follow_up_limit}` — **prefer finished over `error`** (spec §5). Migrate today’s follow-up cap from `fail_run`/`error`/`follow_up_limit` code path to the same finished-style terminal (keep `code` optional on error unused for these).
- Summarizer / middleware LLM calls **do not** increment `guards.llm_rounds` (only `stream_llm` / main loop).
- `write_todos` / other server tools **do** break noop streak (todos changed and/or tool used).
- Client tool turns **break** noop streak.
- `0` means **disabled** for `max_llm_rounds`, `max_run_wall_secs`, and `max_noop_llm_rounds`. `max_follow_up_rounds = 0` means no follow-up allowed after the first text-only exit path would otherwise inject (same as “cap is 0”).
- Wall clock uses `guards.started_at` (unix seconds string already on disk); resume **must** keep original `started_at`.
- Do **not** implement `task` / subagents (LH-M5).
- Do **not** add per-create override of `tool_timeout_secs` (spec marks optional later).
- No fuzzy string crate: noop “高度相似” = trimmed equality of assistant `content` (empty+empty counts as similar).

## Out of scope

- Lease heartbeat (M1.1)
- Client-overridable tool timeout / wall clock on `CreateRunRequest`
- Changing tool wait timeout semantics beyond existing `tool_timeout_secs`
- Desktop UI for guard reasons (document only; client can show `reason`)

## Decisions locked for implementers

| Topic | Decision |
|-------|----------|
| Config section | `[guards]` on `AppConfig` |
| Defaults | `max_llm_rounds=64`, `max_follow_up_rounds=8`, `max_run_wall_secs=3600`, `max_noop_llm_rounds=3` |
| Disable | `0` disables llm / wall / noop caps |
| Terminal shape | `run.finished` + reason; checkpoint `status=completed` |
| Follow-up cap | Config replaces `MAX_FOLLOW_UP_ROUNDS`; reason `follow_up_limit` (keep name for client compat) |
| Noop definition | Consecutive main-LLM turns with: no tool_calls, todos fingerprint unchanged, assistant content trim-equal to previous noop candidate |
| Resume | Seed `PersistSession.guards` (+ noop streak fields if needed) from checkpoint; do not reset `started_at` / counters |
| Check points | After each successful `stream_llm` Completed push; before applying follow-ups when cap exceeded |

### Task 3: Orchestrator enforcement + resume guards

**Files:**
- Modify: `src/agent/orchestrator.rs`
- Modify: `src/api/http.rs`, `src/main.rs`, tests calling `run_agent*`

**Behavioral changes:**

1. `run_agent` / `run_agent_with_options` / `continue_after_pending_tool` take `guards_cfg: GuardsConfig` (or `Arc`).
2. `PersistSession::new` accepts `initial_guards: Option<GuardsSnapshot>`; if `Some`, use it; else `new_now()`.
3. Cold resume / continue: pass `cp.guards.clone()`.
4. After `stream_llm` increments `llm_rounds` and pushes assistant message:
   - Evaluate wall: if `max_run_wall_secs > 0` and elapsed ≥ max → `finish_guard(..., REASON_GUARD_TIMEOUT)`.
   - Evaluate llm rounds: if `max_llm_rounds > 0` and `llm_rounds >= max` → `REASON_GUARD_LLM_ROUNDS`.
   - Update noop tracker from assistant content / todos / `!tool_calls.is_empty()`; if streak ≥ `max_noop_llm_rounds` (>0) → `REASON_GUARD_NOOP`.
5. Replace `MAX_FOLLOW_UP_ROUNDS` check with `guards_cfg.max_follow_up_rounds`; on trip use **finished** path with `REASON_FOLLOW_UP_LIMIT` (update existing orchestrator tests that expect `error` / `FollowUpLimit`).
6. Add `finish_guard(...)` helper: emit `RunFinished { reason }`, `finalize(..., Completed)`, return `Ok(())` **or** a dedicated `OrchestratorError::GuardFinished` that outer spawn treats as success—**decision: return `Ok(())` after finished** so HTTP spawn does not treat guard stop as failure. Keep `OrchestratorError::FollowUpLimit` deprecated/removed if unused.
7. Optional: check wall also at loop top (steer/tool wait can be long)—**decision: check wall at loop start + after LLM** so long tool waits still trip timeout.

**Illustrative:**

```rust
async fn finish_guard(
    run: &RunHandle,
    run_id: &str,
    context: &[WireMessage],
    tools: &[ToolDef],
    ps: &mut PersistSession,
    reason: &str,
) -> Result<(), OrchestratorError> {
    emit(run, SseEvent::RunFinished {
        run_id: run_id.to_string(),
        reason: reason.into(),
    }).await;
    finalize(run, context, tools, ps, RunStatus::Completed).await
}
```

## Milestone exit criteria

| Check | Done when |
|-------|-----------|
| Config | `[guards]` loads with documented defaults |
| LLM rounds | Cap triggers `run.finished` / `guard_llm_rounds` |
| Follow-up | Cap triggers `run.finished` / `follow_up_limit` (no `error` event) |
| Noop | Identical text-only streak triggers `guard_noop`; tools/todos reset streak |
| Timeout | Wall clock from `started_at` triggers `guard_timeout` |
| Resume | Counters / `started_at` survive checkpoint continue |
| Regression | Full suite green |

## Suggested order

Task 1 → 2 → 3 → 4. Do not start LH-M5 (`task`) until M4 exit criteria pass.

## Deploy / client note

Ops tune `[guards]` per environment (GIS long tools → raise `tool_timeout_secs` already; raise `max_run_wall_secs` for long jobs). Desktop should display `run.finished.reason` when present; no protocol change beyond reason strings.
