# LH-M3 Implementation Plan — Plan Mode (`write_todos`)

**Status: completed** (LH-M3 Plan Mode). Historical checkboxes may still show `- [ ]`.


> **For agentic workers:** Implement task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Prefer small commits only when the user asks.

**Goal:** When `options.plan_mode=true`, inject a server-side `write_todos` tool, keep an authoritative todo list on the run (memory + checkpoint), execute updates locally without client `tool.request`, emit SSE `todos.updated`, and restore todos on cold/hot resume.

**Architecture:** Add typed `TodoItem` / `TodoStatus` in `protocol`. Carry `todos: Vec<TodoItem>` on `PersistSession` (today checkpoints always write `todos: []` — fix that). Before the tool-wait loop, classify each LLM `ToolCall`: if name is a **server tool** (`write_todos`), run it in-process; else keep today’s client wait path. Inject `write_todos` into the tools list passed to `LlmPort` when plan mode is on; optionally prepend a short system constraint. Wire `plan_mode` from `CreateRunRequest.options` through `run_agent*` and into cold resume (store on checkpoint / meta).

**Tech Stack:** Existing crate only (serde, axum, tokio, MockLlm). No new dependencies.

**Spec:** [docs/superpowers/specs/2026-09-18-long-horizon-design.md](../specs/2026-09-18-long-horizon-design.md) — §2.3 (`plan_mode`), §4 (Plan Mode), §7 (`todos.updated`), §12 LH-M3.

## Global constraints

- `write_todos` is **full replace** of the list (no merge in M3).
- Server tools **never** emit `tool.request` and **never** wait on `tool_results`.
- If the client also registers a tool named `write_todos`, **server definition wins** (dedupe by name when building the LLM tool list).
- At most one `in_progress` item is a **prompt obligation**, not a hard server reject (invalid statuses / missing fields → tool result `is_error` style content, list unchanged).
- `plan_mode=false` (default): no injection, no system nudge; behavior identical to today.
- Persist is orthogonal: `plan_mode` works with `persist=false` (todos only in memory for that process).
- Do **not** implement `task` / subagents (LH-M5) or guards beyond existing counters (LH-M4).
- Do **not** add `GET /v1/runs/{id}` in M3 unless needed for tests; UI exit criterion is SSE-only.

## Out of scope

- Partial merge / patch semantics for todos
- Auto-updating todos from steer (model must call `write_todos`)
- Parallel client tools in one turn beyond today’s sequential wait
- `subagents`, lease heartbeat, summarizer changes
- Enforcing “one in_progress” as a hard validation error

## Decisions locked for implementers

| Topic | Decision |
|-------|----------|
| Storage type | `Checkpoint.todos: Vec<TodoItem>` (migrate from `Vec<Value>`; serde-compatible JSON) |
| Replace vs merge | Full replace from tool arguments |
| Multi-tool turn | Process **all server tools first** (in call order), then client tools sequentially as today |
| Resume | Load `todos` + `plan_mode` from checkpoint; re-inject tool + system nudge if `plan_mode` |
| System nudge | One short `Role::System` message prepended once at run start when `plan_mode` and no prior identical nudge in context |
| Tool result content | Compact JSON string: `{"ok":true,"todos":[...]}` or `{"ok":false,"error":"..."}` |

### Task 3: Orchestrator — server tool path + persist todos

**Files:**
- Modify: `src/agent/orchestrator.rs`
- Modify: call sites in `src/api/http.rs`, `src/main.rs`, tests that call `run_agent*`

**Behavioral changes:**

1. `run_agent` / `run_agent_with_options` / `continue_after_pending_tool` gain `plan_mode: bool` (and internal `todos: Vec<TodoItem>` on `PersistSession`).
2. When `plan_mode`:
   - `ensure_plan_nudge(&mut context)` once at entry (create + cold resume).
   - Build `effective_tools = inject_plan_tools(&tools)` for **LLM** calls; keep original client `tools` for checkpoint `tools` field (client schema only) **or** store effective list — **decision: checkpoint.tools = client tools only; LLM always sees inject_plan_tools(client) when plan_mode**.
3. Replace hard-coded `todos: vec![]` in `PersistSession::checkpoint` with `self.todos.clone()`.
4. After `stream_llm` returns `tool_calls`, split:

```text
for tc in tool_calls:
  if plan_mode && tc.name == "write_todos":
      match apply_write_todos(&tc.arguments):
        Ok(list) => { self.todos = list; emit TodosUpdated; push tool WireMessage ok }
        Err(e)   => { push tool WireMessage ok:false; do not change self.todos }
      checkpoint(Running, pending=None)   # after each server tool
      # do NOT begin_wait_tool / ToolRequest
  else:
      # existing client wait path
```

5. If a turn has **only** server tools, loop continues to next LLM call (same as today’s “got tools then wait then LLM” but without waiting).
6. `continue_after_pending_tool` / cold resume: seed `ps.todos` from checkpoint; pass `plan_mode` from checkpoint.

## Milestone exit criteria

| Check | Done when |
|-------|-----------|
| Inject | `plan_mode=true` → LLM sees `write_todos` tool schema |
| Server exec | Mock calls `write_todos` → `todos.updated`, **zero** `tool.request` |
| Persist | Checkpoint on disk has typed `todos` + `plan_mode` after update |
| Resume | Cold resume restores todos; further `write_todos` works |
| Default off | `plan_mode=false` → no behavior change vs pre-M3 |
| Regression | Full `cargo test` green |

## Suggested order

Task 1 → 2 → 3 → 4. Do not start LH-M4 (guards) or LH-M5 (`task`) until M3 exit criteria pass.

## Deploy / client note

Desktop (or any) clients: when enabling plan mode, render `todos.updated`; do not implement a local `write_todos` tool. Sticky LB / resume behavior unchanged from M1.
